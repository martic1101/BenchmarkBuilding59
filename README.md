# Building 59 Data Transformation Benchmark (v2)

[繁體中文使用說明](README_zh-TW.md)

By-target data transformation on real building data: from a sample of source data and 5 rows of the target table,
write a program that converts unseen days of the source data into the target table. 601 cases built from the
Building 59 dataset (CSV sensor files, data dictionary, Brick model).

```
BenchmarkBuilding59/
├── README.md
├── evaluation_protocol.md     splits, model input, comparison rules, metrics, checks  ← read this first
├── manifest.csv               case folder ↔ original task id
├── dev/TypeN/CaseNNN/         293 development cases
├── held_out/TypeN/CaseNNN/    308 held-out cases (main experiment Q1 = held_out/Type4, 60 cases)
│     └── input/  hidden/      what the model gets  |  grader / researcher only
├── kg/                        full_knowledge_base.txt (full_kb condition), source_docs.jsonl
├── runners/build_prompt.py    builds the model prompt from input/ only
└── evaluator/evaluate.py      grades a prediction against hidden/ground_truth.csv
```

| Type | Task | dev | held_out |
|---|---|---|---|
| Type1 | temporal aggregation (e.g. 1-min → 30-min mean) | 133 | 134 |
| Type2 | unit conversion, including cases where the dictionary's unit is wrong | 34 | 31 |
| Type3 | join 2–3 files on time after aggregating each | 85 | 83 |
| Type4 | group rooms by equipment (RTU) or floor using the Brick model, then aggregate | 41 | 60 |

## Quick start

Python 3.10 or newer. The release includes all data slices needed to run the cases; the original multi-year
dataset is not required. Prompt building and evaluation do not call a model API or require API keys.

```sh
git clone https://github.com/martic1101/BenchmarkBuilding59.git
cd BenchmarkBuilding59
python -m venv .venv
```

Activate with `.venv\Scripts\Activate.ps1` in Windows PowerShell, or `source .venv/bin/activate` on Linux/macOS.

```sh
python -m pip install -r requirements.txt
```

Read [evaluation_protocol.md](evaluation_protocol.md), then generate a prompt and pass it to your own model or
system. Save the returned Python code, without Markdown fences, as `my_solution.py`:

```
python runners/build_prompt.py held_out/Type4/Case001 none            # the prompt
python evaluator/evaluate.py --case held_out/Type4/Case001 --pred my_output.csv
python evaluator/evaluate.py --case held_out/Type4/Case001 --program my_solution.py
```

The solution must implement `def transform(sources: dict) -> pandas.DataFrame`, where `sources` maps CSV file
names to local paths. The generated prompt specifies the complete output contract. `--program` executes code
in a plain subprocess with a timeout, not a security sandbox; run model-generated code in an isolated environment.
Alternatively, generate the predicted CSV with your own execution system and grade it with `--pred`.

Conditions: `none`, `full_kb`, and `selected_facts`. The last is an oracle knowledge-selection upper bound,
not a retriever's output. Report each condition separately. SQL prompt generation is available with `--lang sql`;
the bundled `--program` evaluator executes Python only. Execute SQL in your own DuckDB environment and submit a CSV.

## Batch evaluation

Save predicted tables at paths such as `predictions/held_out/Type4/Case001.csv`, then run:

```sh
python evaluator/evaluate_batch.py --predictions predictions --split held_out --type Type4 --out results/type4.json
```

Omit `--type` to grade the entire split. The report includes exact-match rate, mean per-case column accuracy,
mean per-case value accuracy, and per-case scores. Missing, unreadable or unparseable predictions score zero
and remain in the denominator. This command only reads CSVs and does not execute submitted code.

Only `input/` may be given to a model. Results that used anything in `hidden/` are not comparable.

Use `dev/` to tune a method, then freeze it before evaluating `held_out/`. Do not give a model or agent access
to the entire checkout: copy only the permitted inputs into its workspace. `hidden/source_test/` is for the
transformation program to read at execution time. The ground truth, reference programs and task specifications
are for the evaluator/researcher only. This is a public benchmark with public answers, not a server-hidden test set.

When reporting results, record the repository commit, split, types, knowledge condition, model/version, generation
settings, and execution environment. Scores and tolerance are defined in the evaluation protocol.

See [VALIDATION.md](VALIDATION.md) for the publication checks and test commands.

Provenance: generated by `src/s05_generate.py` (dev), `s35_make_holdout.py` and `s39_make_holdout_t4novel.py`
(held-out), laid out by `s47_export_typed_layout.py` and `s48_split_input_hidden.py`, verified by
`s49_verify_v2_layout.py` (research code, not included in this repository).

## Data source

All cases are derived from the LBNL Building 59 dataset and its Brick model:

- T. Hong, N. Luo, D. Blum, Z. Wang. *A three-year building operational performance dataset for informing energy
  efficiency.* Dryad, 2022. https://doi.org/10.7941/D1N33Q (published by Dryad under CC0)
- N. Luo et al. *A three-year dataset supporting research on building energy management and occupancy analytics.*
  Scientific Data 9, 156 (2022). https://doi.org/10.1038/s41597-022-01257-x

Please cite the original dataset when using this benchmark.
